## 它是什么

DSH（DeepSeek Harness）在工具需要提权时会停下来问人：`approval/request` 是一条瀑布链，链末端没人应答就等于拒绝。本插件注册成**唯一的裁决者**，在这一刻做三件事：

1. **L0 硬风险直接给你** —— 删目录、丢改动（`git reset --hard` 这类）、碰凭据、远程执行、改系统、批量破坏，一律不问 AI、不进记忆。
2. **重复操作学会放行** —— 同一条无害命令你亲手批满 3 次，之后它自己放（按会话隔离，换会话重新学）。
3. **其余交给 AI 预审** —— 一次小模型调用（≈300–500 tokens），只允许两个结论：`allow`（放）或 `ask`（拿不准，交给你）。**AI 没有否决权**。

因为裁决者唯一，每条记录的"谁放的"是事实而不是猜测：`ai` / `memory` / `human` / `external` / `fallback`。

> **AI 预审默认覆盖 ops 插件的命令**：[dsh-ops](https://github.com/T-Auto/dsh-ops) 发布的 `ops_bash` 与只读的 `ops_read_files` / `ops_grep` / `ops_glob` / `ops_inspect_local_file` / `ops_status`、以及它的后台任务工具 `job_output` / `job_list` 都在默认 AI 名单里——不用额外配置，装好就会预审它们。其它工具（`write` / `edit` 等）走记忆档，`plugin_manager` 这类默认直接问你；要增减都在插件页「高级设置 → 先交给 AI 的工具 / 不交给 AI 的工具」里改。

## 决策链

一次 `approval/request` 进来，按**固定顺序**过四道关：谁先命中谁负责，后面的层不再参与。

```
① L0 硬风险（确定性，不花钱）
     ├ 命中 → 直接问你；不进 AI、不计入记忆、永不自动放行
     └ 未命中 ↓
② 记忆（确定性）
     ├ 本会话里这条操作你亲手批满阈值（默认 3 次）→ 自动放行
     └ 未命中 ↓
③ 文件级（确定性，需你显式开开关）
     ├ 这个文件的人工批准次数 ≥ 阈值 → 自动放行
     └ 未命中 ↓
④ AI 预审（一次小模型调用，≈300–500 tokens）
     ├ allow → 放行（decidedBy = ai）
     └ ask   → 交给你；AI 没有否决权，只能放行或提问
              ↓
⑤ 人工
```

顺序不是随意的：**确定性在概率之前**。凡是规则能判的（硬风险、记忆、文件级）一律不交给模型；模型只处理"剩下那些无害、但还没见过"的请求。

每条记录都写明是哪一层做的决定：`ai` / `memory` / `human` / `external` / `fallback`，并附带 `agentKind`（请求方）、`tier`（档位）、`aiSource`（AI 是否真的审过）。事后想回答"这条为什么没让 AI 看"，看这三列就够了；被 AI 打回、再由你决定的那些，行内会标 **AI 打回 · 人工通过/拒绝**，日期左边写着真正做判断的评审模型。

## 你会看到什么

- **输入框上方**一张淡色卡片：AI 通过（淡绿）/ 记忆通过（淡蓝）/ 待审批（淡黄），右侧有复制和关闭按钮；没有审批时整行不出现，不占地方。
- **别的会话**有审批时只出一张灰色聚合卡：`会话名 · AI通过 0 · 记忆通过 1`，不和当前对话混在一起，只能手动关。
- **对话顶部「审批」标签**：完整时间线（工具、归属、理由、参数、耗时、记忆进度），放大镜找历史；有新审批时标签出现 🔴 红点，列表用 `—— 以上为新增审批 ——` 把"看过的"和"新的"隔开。
- **右侧栏「改动」**：点某行的「改动」看那一次调用的 diff（双行号），一键撤销（连点两次确认，3 秒不点作废）。
- **需要你决策时**，提示卡和系统通知直接写着 AI 的意见：`AI 建议人工 · high · 理由说读文件但命令会删目录` —— 批之前你就知道 AI 看到了什么。
- **需要你决策时**还有一张**悬浮卡**（右上角），内容与输入框上方那张一致——宿主的人工审批面板会盖住输入框上方那条，这张浮在窗口层。
- **台账导出**：CSV / JSON，按会话或全部。

## 和同类插件的关系

DSH 的审批生态里已经有不少插件，思路各不相同。本插件把这些思路里**能共存的那些**收进一个实现：确定性优先的硬风险层（不需要模型）、AI 预审层（只能放行或转人工）、按会话的学习层，以及完整的面板/diff/撤销。

如果只记四条差异，是这四条（其余都是实现细节）：

1. **AI 只有 `allow` / `ask`，没有否决权**——`deny` 被强制降级成「转人工」。多数同类插件让模型直接拒（fail-closed），一次误判就变成拒绝执行。
2. **记忆只数「人工批准」**——AI 或记忆自己放行的次数不推进计数器，所以「学满自动放行」的每一分证据都是人给的，可审计。
3. **模型只看脱敏摘要**——送审的是压缩后的参数摘要（路径/命令裁剪过），不是原文；凭据类路径连摘要都不给。
4. **有完整的审批 UI**——时间线、diff、撤销、CSV/JSON 台账导出，而不是「弹一下就没了」。

### 和 `dsh-auto-approve` 的逐项差异

它是**权限预设**：新增一档 `sandboxed-auto`，只有选了这档的会话才动作，其余请求原样透传。明镜是**审批链 answerer**：不改任何预设，任何档位走到审批时都过同一套链。这个定位差别决定了下面每一行。

左列按对方 **0.7.1** 的 npm 包与 README 核对（2026-11-09），右列是本仓库的代码事实：

| 维度 | `dsh-auto-approve` 0.7.1 | 明镜 |
|---|---|---|
| 挂载方式 | 新增第五权限预设，preset 匹配才动作 | `approval/request` 瀑布上的 answerer，全预设统一生效 |
| 审查范围 | 只管沙箱 escalation（作者估算约 2% 调用） | 所有走到审批的请求，按 `tier` 分流（AI / 记忆 / 直接人工） |
| AI 否决权 | **有**：危险清单命中或分类器拿不准就转人工，但「never 档」可硬拒 | **没有**：`deny` 被强制降级成 `ask`（`review.js`） |
| 失败语义 | 分类器失败回落人工 | 同向：任何失败（无 llm / 熔断 / 超预算 / 超时 / 解析失败）一律 `ask` |
| 确定性危险清单 | 有，先于分类器 | 有，先于记忆与 AI（L0：删除 / 丢弃改动 / 凭据 / 远程执行 / 系统级 / 批量破坏） |
| 记忆 | 同工具 + 同参数字节级哈希，**进程内内存 + TTL 30 分钟**，重启即失，无 UI | **持久落盘 + 阈值**（默认 3 次人工）+ per-session + 旋钮归一化（`limit`/`offset`/`description` 等不参与指纹）+ 记忆页可视、可逐条删、可按文件开自动放行 |
| 计数来源 | 分类器批过的也计入 | **只计人工批准**——AI 或记忆自己放行的不推进计数器，避免自我强化 |
| 给模型看什么 | 命令 + justification + 沙箱目标 + 工作区 + **完整用户消息全文**（≤2000 字符，超长直接转人工） | **只给脱敏摘要**（≤240 字符，`sk-` / `Bearer` / 密钥字段名全部 redact），凭据类路径连摘要都不给 |
| 审计 | 宿主原生 approval 事件 + 进程内报告（重启即清，作者自述不是审计账本） | 自有台账（`decidedBy` / `agentKind` / `tier` / `aiSource` / `threshold` 冻结）+ 审批页 / 记忆页 / 统计页 + CSV/JSON 导出，跨重启 |
| UI | 无（README 自述） | 侧栏四个 Tab + 输入框上方提示卡 + 悬浮 AI 建议卡 + diff / 撤销 |
| 模型成本 | 每次 escalation 一次分类调用 | 每次 AI 档一次调用，另有 60 秒窗口预算、熔断、持久化裁决缓存（TTL 内重放零成本） |
| 已知敞口 | 对方 README 自述：默认提示词会放行写 `~/.dsh/profiles/`，等于运行时自改供应链路径敞开，需手工关 | 无同类：凭据类路径落 L0 硬拦，写前快照对这些路径不存正文 |
| 规模 | 11 文件 / ~180 KB | 12 个服务端模块 + 单文件客户端，96 条测试 |

**两者可以共存**（它管 escalation，明镜管整条审批链，不冲突），所以不必二选一。真要选，就按三条看：①**否决权在谁手里**——它能被 AI 拒，明镜的 AI 只会说「建议放行」或「交给你」；②**学习能不能审计**——它 30 分钟内存哈希，明镜跨重启、只计人工、逐条可查可删；③**数据边界**——它把用户原话全文送模型，明镜只送脱敏摘要。
更细的逐个拆解（机制、可借鉴点、版本号、下载量）见 [RESEARCH.md](RESEARCH.md) §4，那份文档带采集日期。

> ⚠️ 冲突只发生在**也在 `approval/request` 上作答**的插件之间：两个 answerer 抢答时归属会显示成 `external`，审批可能被它们先答掉。装本插件前请把这类插件从 profile 移除，并确认 `/health` 的 `counters.external` 恒为 0。

## 安装

写进 profile（`~/.dsh/profiles/desktop`），而不是跑 `npm install`：

1. `package.json` 的 `dependencies` 加 `"dsh-review-hub": "link:<本仓库路径>"`；
2. `bundles` 数组加 `dsh-review-hub`，并移除**其它会作答 `approval/request`** 的审批插件（见上一节；纯通知类可留，但要确认不抢答）；
3. 用 DSH 自带的 pnpm 执行 `install --lockfile-only`（**不要**全量 install，会清掉原生模块构建）；
4. 建 junction：`node_modules/dsh-review-hub` → 本仓库目录；
5. **检查 `cordis.patch.yml`**：任何带 `name:` 的旧补丁行都会在 bundle 行删掉后继续把插件挂回来；
6. 重启宿主（服务端半身加载时绑定；客户端半身刷新页面即可）。

详细步骤与踩坑见 [README-AI.md](README-AI.md) 与 [docs/PLAN.md](docs/PLAN.md)。

## 设置在哪

- **日常设置** → 对话顶部「审批」标签页里的「设置」：AI 审查、审查模型、记忆自动通过、放行阈值、提示卡、三档卡片时长、系统通知。开关是主机同款滑块，每项下面一句人话。
- **审查模型**是两级下拉（先选 provider、再选模型），名单来自宿主自己的模型目录（`llm.listProviders()` + 每个 provider 的 `listModels()`），默认 `跟随会话`；下面一行小字「实际使用」告诉你此刻真正在用哪个车道，尾部刷新图标可手动重拉目录。目录为空（宿主没接 llm）时才退回手填。
- **高级设置（不要乱改）** → 插件页的插件卡片：兜底轮询间隔、保留条数、审查超时、每轮上限、熔断次数、按请求方分档、**先交给 AI 的工具**（只填增量，内置基线写死在代码里）与**不交给 AI 的工具黑名单**（黑名单优先，能盖掉内置基线；write / edit 属记忆档，两边都动不了它）、**卡片预览**（常驻：就地渲染五种卡片 + 本会话实时 + 两个悬浮卡自测按钮），以及**启用「清空历史」**（默认关；开启后仍需连点三次，服务端也校验这个开关）。

## 常见问题

**Q：为什么 AI 没出现就直接问我？**
硬风险（6 类）根本不进 AI；或者没有可用模型服务、请求超时、熔断中。记录会写明 `aiSource`。

**Q：AI 会不会把危险操作放过去？**
**会——但具体要看对应模型的能力和你是否信任 TA，这也是这套设计唯一真正的风险点。** AI 判 `allow` 时，这一次审批就不再问你了，所以这个问题的答案取决于两件事：那条车道上的模型到底能不能看懂这段命令，以及你是否愿意把自己的一部分判断交出去。

但能约束的部分已经约束住了：① 6 类硬风险（删除、丢改动、凭据、远程执行、系统级、批量破坏）根本不送 AI，直接找你；② AI 只看到脱敏后的参数摘要与理由，判定标准写死为"可逆、范围明确、与理由一致"，拿不准就必须 `ask`；③ 你可以随时关掉 AI 审查，也可以在高级设置里把工具拉黑、或把某个请求方档位调严。剩下的那一小块——模型的判断力——不是这套设计能替你保证的；时间线就是给你复核用的。

**Q：为什么批了很多次它还没学会？**
记忆只统计**人工**批准（AI 通过、记忆通过都不计数，否则会自我强化），硬风险永不学习；进度显示为"记忆 n/3 次"。

**Q：AI 用哪条线路？花多少 token？**
默认跟随当前会话的模型，也可以在设置里钉一个便宜车道。它只看到脱敏后的参数摘要（≤240 字符）与理由，一次约 300–500 tokens；裁决结果落盘缓存，重启后不重复花钱。

**Q：推荐使用什么模型？**
够用就好，贵不等于好，但参数越小越容易出错。

**Q：能多开窗口吗？**
能，但两个窗口各自记"已看/基线"，红点可能不同步。

## 安全边界

写清楚这里能防什么、不能防什么，比含糊其辞有用。

- **谁能读到这些数据**：插件的 HTTP 面（`/api/review-hub/*`）只监听宿主自己的 loopback 端口，并校验 `Host` 是回环地址、`Origin`/`Referer` 与之同源（桌面壳的 `dsh-app:` 协议单独放行）。**没有额外的 token**，也**没有**「请求必须来自浏览器」这层校验——实测桌面壳的请求既不发送 `Origin` 也不发送 `Sec-Fetch-Site`，加这层校验会把面板整个打成 403（2026-11-09 真机验证）。所以本机上的任何进程，只要能连到那个端口，就能读写台账与设置；宿主端口每次启动随机分配（`--port 0`）是目前唯一的实际屏障。想收紧有两条现成的路，都在插件配置（不是面板设置）里：

- `strictOrigin: true` —— 要求 `Sec-Fetch-Site`。默认关，因为桌面壳不发这个头，开了面板会全 403。
- `writeProofCookie: "<cookie 名>"` 或 `writeProofHeader: "<头名>"` —— **只拦写方法**（`POST`），读与 SSE 不受影响。默认空 = 关。这个值不该靠猜：先用 `debugHeaders: true` 把每个请求的 header 名与 cookie 名记到 `~/.dsh/storages/review-hub/http-probe.log`（只记名字，不记值；最多 400 行），对比面板与 `curl` 的差异，再把面板独有、`curl` 没有的那一个填进来。
- **磁盘上有什么**：`~/.dsh/storages/review-hub/` 下有台账（每条审批的工具名、参数、理由、判定者）、记忆表、设置、AI 裁决缓存，以及 `snapshots/` —— 后者保存 `write`/`edit` 目标的**改前全文**（单文件上限 256KB，每会话最多 64 条）。也就是说：**你批准过的文件内容，会以明文留在这台机器上**，包括你编辑过的 `.env`、配置文件。
- **怎么清掉**：删除整个 `~/.dsh/storages/review-hub/` 目录即可（插件下次启动会重建）。审批页的「清空历史」只清台账与记忆，**不动 `snapshots/`**。
- **AI 层看到了什么**：只送脱敏后的参数摘要（≤240 字符）与理由，不送完整文件内容；裁决结果落盘缓存，重启不重复计费。
- **AI 没有否决权**：它只能说 `allow` 或 `ask`。`deny` 会被降级成 `ask`——这条是硬约束，见 [README-AI.md](README-AI.md)。

## 性能

空闲时**零请求**（一条本地 SSE 挂着，30 秒一次心跳）；审批事件一条一帧（实测单条记录 ≈630 字节，本机约 0.5 次/小时）。断流自动退到 3 秒轮询；窗口最小化时断流，不唤醒渲染进程。

## 已知限制

- 深绑 DSH 内部结构（席位名、右侧栏 API、`--dsh-composer-*` CSS 变量），宿主大版本升级可能要适配；
- 客户端是一个约 4100 行的单文件 bundle（没有构建步骤）；
- 审批页按会话，没有"所有会话汇总"视图；
- 撤销是"投递指令给会话"，需要该会话还有可用 agent；
- 写前快照有上限（单文件 256KB / 每会话 64 条），超限只能看元数据。
